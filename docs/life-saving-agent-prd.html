01产品定位与目标

帮助有控制生活开支意愿的用户，看清“已经买的值不值”，找到“接下来买哪里便宜”。

能力 A · 账单 → 资产 → 日均成本

导入支付或购物账单，自动识别可长期使用的商品，生成资产记录。用户可快速确认或修正，系统持续计算持有日均成本。

能力 B · 商品名 → 跨平台 → 价格结论

输入商品或生活服务名称并确认规格、地区与履约方式，在电商及美团等生活服务平台中查找报价，按各平台优惠规则计算可核验到手价，给出最低价、适用条件及操作步骤。

目标用户与核心任务

用户情境要完成的任务成功结果
整理过去的消费一次导入账单，减少逐件录入可追溯的资产清单，自动计算日均成本

首版假设：面向中国大陆个人用户，简体中文，人民币 CNY，自用实物资产；日期与账单时区统一为 Asia/Shanghai。这里的“资产管理”指生活物品管理，不涉及银行卡余额、投资组合或财务报表。

04账单导入需求

ID需求行为与约束
B-01 上传CSV / XLSX 文件导入单文件 ≤ 20 MB，≤ 50,000 行；CSV 支持 UTF-8 / GB18030，XLSX 可选工作表。未知模板进入映射向导；不执行宏和单元格公式，不打开文件内链接。
B-02 字段映射自动识别 + 人工修正必填：交易时间、金额、交易描述或商品名；其余：交易号、订单号、平台、商户、收支方向、交易状态、数量、退款关联号。金额只接受可解析数字，币种首版仅 CNY。方向缺失需用户确认整批规则或逐行修正。
B-03 导入预览正式提交前展示识别结果展示总行数、有效 / 重复 / 错误数量和前 20 条样例；日期格式歧义、负数含义、方向映射必须明确。错误行可跳过，有效行继续；无有效行时禁止提交。
B-04 交易去重重复导入不重复计入优先用用户 + 来源 + 交易号判重；无交易号时，以时间、金额、方向、商户、描述指纹标记疑似重复，交用户判断。同笔微信 / 支付宝支付与电商订单跨源重复需关联候选，未确认前暂停相关资产自动入库。
B-05 资产识别区分资产、普通消费与非消费明确的手机、家电、电脑、家具、可长期使用衣物等进入资产识别；餐饮、交通、房租等归普通消费；转账、充值、还款不生成资产。只有商户名、订单组合包无法拆分、型号不清或支付状态不明时进入待确认。
B-06 自动入库高置信度资产直接加入仅成功支付、方向为支出、非重复、金额确定且商品明确的交易可自动建档。置信阈值和规则版本可配置；其余进入待确认。每条记录展示原始账单和识别理由，支持“改为普通消费”和“撤销入库”。
B-07 数量 / 组合订单避免一笔金额重复分摊明确购买 n 件同款时，可建数量为 n 的资产组，净成本记录整组金额；日均成本也是整组成本。多种商品需分配金额，各分项金额之和必须等于可分配净支出；分配前不进入资产汇总。
B-08 退款与取消维护买入净成本取消 / 失败订单不建资产；部分退款扣减资产净成本；全额退款且退货将资产设为已退货，移出在用汇总。平台价保类退款可保留在用状态。退款优先按原交易 / 订单号关联，歧义进入待确认；退款累计不得超过可退本金。
B-09 结果与恢复导入批次可追踪显示进度、成功与失败数量，下载含行号 / 原值 / 错误原因的报告，支持修正后重试。批次撤销不影响其他有效来源；若资产后续被编辑或被其他批次引用，先展示影响，人工处理冲突后撤销。
自动化限制：支付账单可能只有商户和金额，无法可靠判断具体商品。系统必须保留不确定状态，不得根据模糊商户名编造资产名称、型号、数量或价格分摊。

导入状态

待上传 → 待映射 → 校验中 → 待提交 → 处理中 → 成功 / 部分成功 / 失败。同一批次提交需幂等；失败可重试，已成功的交易不重复创建。待确认项处理后独立更新，不改写原始导入报告。

05资产管理与计算口径

首版主指标定义为持有日均成本，表示买入成本按持有时间摊薄的结果。它不代表实际使用频率，也不代表物品每天消耗的现金或市场折旧。

必需字段与操作

资产包含名称、分类、数量、买入总价、已关联退款、开始使用日、状态、来源与备注。开始使用日默认取购买日；若用户改为收货日或实际启用日，以修改后的日期计算。提供新增、编辑、归类、查看来源、标记售出 / 报废 / 退货、删除与恢复。

买入净成本 = 买入总价 − 已确认退款（最低为 0）
持有天数 = max(1, 统计截止日期 − 开始使用日期 + 1)
在用资产日均成本 = 买入净成本 ÷ 持有天数
已结束资产截止日期 = 售出 / 报废 / 退货日期
在用资产汇总日均成本 = Σ 每件在用且信息完整资产的未舍入日均成本
计算项规则示例 / 处理方式
日期边界按 Asia/Shanghai 自然日，首日算 1 天；每天跨日更新10 月 1 日开始使用，10 月 20 日为第 20 天。同日导入 / 使用也按 1 天计算。
基础示例净成本除以持有天数耳机买入 ¥1,000，退款 ¥100，持有 30 天：¥900 ÷ 30 = ¥30.00 / 天。
金额与精度原金额以分存储，计算保留精度，展示四舍五入到两位小数正值低于 ¥0.01 展示“< ¥0.01 / 天”；汇总先加未舍入值再展示。
缺失或未来日期不猜测、不计入当前汇总无日期为待完善；未来开始日期为未启用，到了开始日再纳入。
售出 / 报废冻结结束日的持有成本，从在用汇总移除可选录入转卖收入；另展示“回收后日均成本 =（买入净成本 − 转卖净收入）÷ 持有天数”，允许负值，标签解释为净回收收益。
退款回溯以当前已确认退款重算当前值首版不提供历史成本曲线；编辑日期 / 金额后立即重算，并记录修改日志。
数量变化资产组整体结束；部分售出需先拆分拆分后各项成本合计保持原总成本，避免整组成本被重复计算。
汇总展示：顶部展示在用买入净成本、在用资产数、在用资产汇总日均成本，并注明“各物品日均分摊成本之和，不是每日现金支出”。资产组按一条记录计数，另显示件数；待确认、未启用、已结束和信息不完整资产不计入。

状态与生命周期

待确认 → 未启用 / 在用 → 已售出 / 已报废 / 已退货。待完善是数据质量标记，可与业务状态并存。结束日期不得早于开始日期或晚于今天；恢复在用需清除结束日期并重新计算。删除进入回收站，30 天后清除；被删除资产的来源交易保留“不再自动建档”标记，避免重导后意外恢复。

06商品与生活服务比价

搜索输入与同款识别

接受自然语言商品名，如“戴森 V12 全新，官方保修”。Agent 解析品牌、型号、规格、容量、套装、数量、新旧状态、地区版和保修条件，展示为可编辑筛选项。全新为默认，二手需用户开启。必要时询问省 / 市以计算运费和地区补贴，不强制索取详细地址。

同款候选按“精确匹配 / 待确认 / 不匹配”分类。精确匹配要求关键规格一致；配件、订金、租赁、空盒、不同容量和不同套装不得进入同款最低价。无法确认的候选单独展示并说明差异，不得参与推荐排序。

比较场景与服务等价条件

场景可参与同组最低价的条件必须单独展示的差异
电商 / 即时零售实物同品牌、型号、规格、数量、新旧及保修条件；用户接受的配送范围与时效快递与即时配送默认分组；只有用户明确接受不同配送方式且均满足其时效要求时才合并比较，并展示差异
外卖 / 自提同一实际门店、菜品 / 规格 / 配料、份数及配送地址或自提门店；满足预计送达 / 取餐时间外卖与自提默认分组；同名连锁不同分店不能自动视为同门店；起送价和必选配料计入校验
到店团购 / 服务套餐同一实际门店、服务项目 / 套餐内容、适用人数 / 次数、预约日期时段、节假日限制与必付费用退款规则、预约限制、有效期、不包含项目均需展示；内容或关键使用条件不同的套餐单列为替代方案

美团、大众点评等平台作为候选来源，并不预设每个 App 都提供以上全部场景。同一底层报价在多个入口出现时，以实际门店 / 商品标识与报价来源去重，并披露来源关联；仅同一数据源的镜像不能作为两份独立报价满足上线门槛。餐饮、服务和团购券属于消费，不因进入比价结果自动加入实物资产。

到手价定义

可比较到手价 = 当前商品 / 套餐报价 + 必付配送费 + 包装费 + 服务费及其他必付费用 − 本次尚未扣除的可核验优惠
单位价 = 可比较到手价 ÷ 相同计量单位数量（仅支持可明确换算的规格）
  • 当前报价已扣除的折扣不得再次减免；每项优惠标记是否已含在报价内。优惠按平台规定的门槛基数、互斥、叠加、封顶、适用顺序及逐步取整规则计算；无法验证的优惠不计入已确认价。
  • 默认排序仅使用所有用户可直接获得、且当前可核验的条件。会员、新人、以旧换新、分期、地区补贴、凑单满减等单独标“条件价”，用户明确符合条件且规则及权益已核验后才参与对应排序。未持有券但可领取的方案另列“领券后条件价”，领券成功且仍有效后方可作为已确认价。仅口头确认资格不能证明券库存、可用性和可叠加性。
  • 优惠卡展示领取方式、门槛、截止时间和可用依据。运费、强制费用或优惠资格未知时标为“价格待确认”，不与完整到手价混排。
  • 二手商品独立分组，按型号、成色、保修、配件和卖家说明比较；成色不一致时明确提示差异，不输出跨成色的统一最低价。
  • 多件商品同时展示总到手价与单位价，默认比较用户指定数量的总价；不得仅凭单位价推荐超出购买数量的套装。
ID需求结果要求
C-01 并发查询对已启用且支持当前品类的平台发起查询逐个平台展示等待 / 成功 / 无结果 / 超时 / 不支持；部分完成即可显示已有结果，单平台失败不阻塞整体。
C-02 商品卡片提供可判断是否同款的信息商品标题、图片（有来源时）、关键规格、平台、店铺 / 卖家、全新 / 成色、保修、库存 / 地区限制、商品价、费用、优惠、到手价、采集时间和来源链接。
C-03 推荐排序符合筛选条件的完整到手价升序显示“本次已查询平台内最低已确认到手价”。同价并列最低，以平台配置顺序稳定展示，不虚构服务质量排名。允许按平台 / 新旧 / 保修筛选。
C-04 覆盖说明说明结论的有效范围展示本次查询平台总数、成功数、失败数和无结果数。只剩一个平台有报价时，提示“仅一个平台有有效报价，暂不能完成跨平台比较”。
C-05 来源与新鲜度报价必须可追溯展示北京时间时间戳与直达链接；默认缓存有效期建议 15 分钟，过期标记且移出有效最低价。可重新查询；平台要求更短有效期时以更短值为准。
C-06 用户行动点击跳转查看原商品跳转前展示“价格与库存以商品页及结算页为准”；不代购、不代付。已失效或明确下架链接停用并允许重新搜索。
C-07 异常报价处理缺价、极低价和不一致无来源、库存未知、运费未知、标题与规格矛盾等转待确认；明显异常低价需二次验证规格、数量和费用。只有单条候选时不依赖统计异常判断，按完整性规则审核。
C-08 优惠方案输出规则约束下的最低已确认方案逐项解释优惠基数、顺序、互斥、资格、领取状态与有效期；付费获取权益的支出另列。规则或证据缺失时显示待确认，不声称可复现最低价。
C-09 生活服务按实际门店与服务条件比较保存门店映射证据、套餐内容、人数 / 数量、履约方式、使用时段、预约与退款规则、配送 / 包装及必付费用。可用性与内容不一致的结果不混排。
C-10 场景覆盖查询与降级按业务场景判断支持某平台电商不等于支持其外卖或团购；逐一披露场景和区域覆盖，未接入生活服务时明确提示，不返回编造的生活服务报价。
